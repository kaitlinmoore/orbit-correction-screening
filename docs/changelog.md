# Changelog

Instrument and design changes, one line each: date | instrument | change | reason. Each entry
says whether held-out data was involved.

- 2026-11-23 | environment | Python 3.12 with uv; uv environment in the WSL filesystem (`$HOME/.venvs/orbit-correction-screening`, via `.envrc`); runtime deps numpy, scipy, sgp4, astropy, pyarrow, requests, python-dotenv; dev deps pytest, ruff, ipykernel. No PyTorch, PhysicsNeMo, Orekit or brahe yet | scaffold for the CPU-only core modules; later steps add their own dependencies. No held-out data involved.
- 2026-11-23 | contracts | first version of the trajectory (GCRF, km, km/s, TT seconds since J2000.0), residual dataset schema (curvilinear RTN targets, cheap minus truth, in the cheap state's frame) and correction interface in `types.py` | contract stubs every later step builds against. No held-out data involved.
- 2026-11-23 | frames / EOP | astropy IERS auto-download off; EOP from the `astropy-iers-data` package pinned in `uv.lock` (0.2026.11.23.0.35.53); conversions outside the EOP table raise | reproducible offline conversions; astropy's `iers_degraded_accuracy` setting alone did not stop out-of-range use. Open decision whether to read the orekit-data `finals2000A.all` instead (low stakes for TEME -> GCRF: UT1 and polar-motion errors cancel there). No held-out data involved.
- 2026-11-23 | space weather (as-of rule) | model-input lookups read OBSERVED rows only; a day's daily values count as known from 00:00 UTC the next day, a 3-hour ap value from the end of its interval; extra publication lag 0 days; trailing 81-day F10.7 mean requires all 81 days | no future information in model inputs; the centred 81-day mean uses 40 days after the date. No held-out data involved.
- 2026-11-23 | space weather (Orekit copy) | writer fills blank Kp/Ap/Cp/C9/Q with 0 only outside the propagation range plus 3 days before and 1 day after; refuses any blank inside it, including the Q flag; appends an empty MONTHLY_FIT block | Orekit 13.x cannot parse the published file; placeholders must never reach a propagated date. No held-out data involved.
- 2026-11-23 | catalog filters (PENDING APPROVAL) | perigee >= 250 km and apogee <= 2000 km; 0 < B* <= 0.01 /ER; EPHEMERIS_TYPE 0 only; object types PAY, R/B, DEB; payloads with current SATCAT status +, P, B, S or X dropped; names starting STARLINK, ONEWEB, KUIPER, IRIDIUM, GLOBALSTAR, ORBCOMM, QIANFAN or GUOWANG dropped; objects whose mean semimajor axis rises > 1 km between consecutive element sets dropped | proposed defaults for the LEO, non-maneuvering, usable-B* regime; values in `config/catalog_filters.toml`. No held-out data involved.
- 2026-11-23 | splits (PENDING APPROVAL) | seed 20261123; held-out object fraction 0.2; dev fraction 0.15 of the rest; time cutoff 2025-01-01T00:00:00 UTC with whole 7-day windows before it; ten validation-case objects forced into the held-out set; training windows overlapping [TCA - 7 d, TCA + 1 d] of a validation event excluded | proposed values in `config/splits.toml`; no split has been generated from real data. No held-out data involved.
- 2026-11-23 | catalog filters | approved: status set to "approved 2026-11-23"; values unchanged from the proposal (perigee >= 250 km, apogee <= 2000 km, 0 < B* <= 0.01 /ER, EPHEMERIS_TYPE 0, PAY/R/B/DEB, status and name rules, SMA-rise 1 km) | decision by Kaitlin. No held-out data involved.
- 2026-11-23 | splits | approved: status set to "approved 2026-11-23"; values unchanged (seed 20261123, held-out 0.2, dev 0.15 of the rest, cutoff 2025-01-01T00:00:00 UTC with whole 7-day windows, ten forced objects, event exclusion [TCA - 7 d, TCA + 1 d]) | decision by Kaitlin; no split generated from real data. No held-out data involved.
- 2026-11-23 | catalog filters (name rule) | added FLOCK and LEMUR to the excluded name prefixes | Planet's Flocks phase with differential drag (arXiv:1509.03270); Spire's Lemurs carry ThrustMe iodine propulsion for phasing, collision avoidance and deorbit from the Q4 2022 launch on (SatNews, 2022-09-02). All Lemurs go, since names don't separate generations. No held-out data involved.
- 2026-11-23 | catalog filters (element-history rules) | added `no_sma_unexplained_drop` (drop between consecutive element sets > 3 x the drag decay implied by MEAN_MOTION_DOT over the gap, larger of the two sets' rates, + 1 km) and `no_inclination_jump` (mean-inclination change > 0.05 deg) | the SMA-rise rule missed orbit-lowering burns and plane changes. Thresholds chosen to pass pure drag decay with fit noise and a tripled decay rate on synthetic histories; small maneuvers still slip under them. No held-out data involved.
- 2026-11-23 | splits (data end) | windows of any split ending after the last fully observed space-weather day (end of that UTC day; `SpaceWeather.last_fully_observed_date`) are labeled `excluded`; the day is passed in at labeling time and must be recorded with a generated split | beyond it the file holds only forecasts, so truth there would be driven by predictions. No held-out data involved.
- 2026-11-23 | splits (reserved rows) | stated that `reserved_object` and `reserved_time` rows enter neither training nor evaluation | decision by Kaitlin. No held-out data involved.
- 2026-11-23 | contracts / model inputs | the model's space-weather inputs are exactly four start-of-prediction values (`types.SPACE_WEATHER_MODEL_INPUTS`: last complete day's observed F10.7, trailing 81-day F10.7 mean, last complete day's daily Ap, last completed 3-hour ap), whole-day-complete availability with lag 0; `obs_*` columns optional, comparison only | decision by Kaitlin; the schema columns were already these four, so the change names them and adds a contract test. No held-out data involved.
