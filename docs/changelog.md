- 2026-11-23 | cheap propagator (SGP4) | `cheap_prop.py`: WGS-72 constants, operation mode `'i'`; `Satrec` built with `sgp4init` using the TLE reader's unit conversions rather than `sgp4.omm.initialize`; time since epoch from TT differences (`(t_TT - epoch_TT) / 60`), not UTC Julian dates; trajectories truncated before the first SGP4 error, with a per-object status (code, message, states kept) | WGS-72 and mode `'i'` are what element sets are fitted with and what Vallado's verification output uses; the library's OMM reader differs from its TLE reader in the last bit of mean motion, which reached 4 mm on two deep-space verification cases; a UTC-date clock loses 1 s (~7.6 km in LEO) across a leap second; SGP4 output after an error isn't trustworthy. Whether downstream steps drop truncated windows is open. No held-out data involved.
- 2026-11-23 | frames (fast TEME -> GCRF) | added `teme_to_gcrf_fast`: the exact rotation computed at nodes every 6 h on a fixed TT lattice, degree-5 Lagrange interpolation between them, nodes cached; falls back to the exact path near the ends of the EOP table; `teme_to_gcrf` unchanged | the exact path costs ~0.6-0.7 ms per state and would dominate catalog-scale generation; measured against it over 7 days at 60 s (2005, 2016 across the leap second, 2024): under 1 micrometre and 1 micrometre/s, about 100x faster per object-week with an empty cache and about 1,900x with cached nodes. No held-out data involved.
- 2026-11-23 | screening engine (event definition) | an event is a local minimum of range between a pair with miss distance <= the threshold at its TCA and TCA inside the window; a pair can have several; pairs unordered (id_1 < id_2); threshold given as a function of time from the screening epoch (`screening.SphericalThreshold`), behind a volume protocol an RTN volume can implement later | matches the Aerospace / Department of Commerce test-set definition and lets cheap screens pass d_truth + pad(tau). Synthetic data only; no held-out data involved.
- 2026-11-23 | screening engine (search and refinement) | cubic Hermite interpolation of the 60 s states; k-d tree candidate search at 2 sub-samples per interval with radius = local threshold + V h/4 + 1 m, V = 2 max sampled speed + speed-change margin (~16 km/s in LEO); convex-hull interval bound; range minima from sign changes of the degree-5 range-rate polynomial (16-point bracket, bisection) | proven not to miss a between-sample minimum at any relative speed up to V; 2 sub-steps fastest at 500 and 2,000 objects. Accuracy at 60 s: TCA within 7 us and miss within 2.6 cm on 40 random synthetic encounters. No held-out data involved.
- 2026-11-23 | classical filters | apogee/perigee (elements or sampled radial extent), orbit path (relative-node start plus damped Newton on the eccentric anomalies; near-coplanar pairs kept; elements propagated with J2 secular rates to the sample times, or pre-sampled elements), time filter (|sin theta| <= d / (q sin I) node windows from Kepler's equation, J2 secular rates, geometry recomputed every 3,600 s, time pad); each with a distance pad; no pad values chosen | classical baselines for the screening comparison, following Hoots et al. (1984) as described by Woodburn et al. (2009) and Alfano and Finkleman (2013). Pads are an open decision. No held-out data involved.
- 2026-11-23 | screening metrics | recall per event and per pair against a reference table, one-to-one matching on (same pair, |dTCA| <= tolerance), tolerance configurable (None = pair only); false alarms per event (unmatched candidates) and per pair (candidate pairs with no matched event); recall for reference events with tau <= 1, 3, 7 days; filter recall (event kept if its pair is kept) and pruned fraction; wall-clock cost carried with each result | instruments for the screening comparison; headline counting rule and TCA tolerance left open. No held-out data involved.
- 2026-11-23 | screening engine (search bound) | relative-speed bound V now comes from the control polygon of each object's interpolated velocity on each interval (speed <= max(|v_k|, |3 (r_k+1 - r_k)/h - v_k - v_k+1|, |v_k+1|)), summed over the two fastest objects, per interval; replaces 2 x (largest sampled speed + mu / r_min^2 x h/2) | the old bound assumed the interpolant's speed stays near the sampled speeds, which holds for consistent orbital states but not for corrected trajectories whose velocities don't match their positions; the new bound holds for any state sequence and is tighter (15.0-16.1 vs 15.5-16.6 km/s on synthetic LEO catalogs, 5-11% fewer candidate intervals). Event tables unchanged: 36 old-vs-new tables bit-identical (3 catalogs, 4 thresholds, 1-3 sub-steps), and a brute-force rerun on 3 of the review's catalogs matched 8,233 of 8,233 events. Synthetic data only; no held-out data involved.
- 2026-11-23 | classical filters (orbit path) | pairs with sin I < 1.5 (e1 + e2) are passed through without a path distance (`eccentric_coplanar_factor`, default 1.5; 0 restores the plain relative-node Newton) | with planes close compared with the eccentricities, Newton from the relative nodes settles on a local minimum and overstated the path distance by up to hundreds of km, losing encounters with exact elements; in a sweep against a global search over about 5,700 LEO pairs it overstated only below a ratio of 0.83 and never at 1 or above. Costs about 0.01% of pairs on the synthetic generator and 14-21% of pairs inside tight same-plane clusters. Synthetic data only; no held-out data involved.
